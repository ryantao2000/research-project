# 04 · 计划

计划写事前的设计：要回答什么、分几个Phase、各Phase的中心问题与产出、资源与边界。执行过程在`work/NN_slug/`，发现写在`05_findings/NN_slug/`。

## 维护规则

### 何时建立

用户要求新建，或出现需要独立追踪目标、阶段或交付的工作时建立。普通答疑和局部修复沿用现有计划或直接处理。先查下表和直接相关的findings，说明新计划承接什么。建立计划本身不等于获准执行。

### 建立步骤

1. 取一个未使用的全局编号，文件名`NN_slug.md`；编号与run身份不复用。
2. 按research-project skill的`templates/desk/04_plans/plan.md`写：开头说明用途、承接与状态；多阶段工作先给**Phase总表（Phase｜中心问题｜关键工作说明｜核心产出）**。Phase 0负责基础核验；之后每个Phase有一个中心问题，不把运行步骤机械拆成阶段。编号表达研究逻辑，不代表必须串行。
3. 需要计算、付费或传数据时，在“资源与边界”写清实际需要的资源、上限和待决定项。
4. 在下表加一行，在[看板](../00_INDEX.md)登记；开始执行时再建`work/NN_slug/`，有结果时再建`05_findings/NN_slug/`。

### 建立后的汇报

向研究者说明：这个计划有什么用、整体路线为什么这样安排；逐个概括Phase 0的核验对象和后续各Phase的中心问题、关键工作、核心产出；当前执行到哪里；真正需要研究者决定的那一项。不只报文件路径，不把未执行的阶段说成结果。

### 计划里写什么

| 放在计划 | 放在别处 |
|---|---|
| 目标、范围、Phase设计、完成与停止条件 | 执行过程、失败与恢复 → `work/NN_slug/log.md` |
| 冻结的协议、关键对照、信息边界 | 配置、脚本、run → `work/NN_slug/` |
| 资源上限与待决定边界 | 比较、图、结论 → `05_findings/NN_slug/` |
| 头部一行当前状态 | 逐节点进度 → work INDEX |

### 修订与收尾

- 追加独立工作时在末尾新增Phase，写明中心问题、依赖与产出；已执行Phase的设计不回写，改变后续做法时在修订记录追加。
- 旧计划由新计划承接时两边互链，旧文件保留。
- 完成时对照各Phase产出说明完成、失败或未执行的部分；工程完成与研究结论分开写。
