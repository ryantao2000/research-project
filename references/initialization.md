# 初始化与升级

新项目先明确研究目标、现行授权、方法权威和必要入口，再按真实工作创建目录。中文、公式格式是个人默认；机器、费率、时区、资源上限与Git布局采用项目实情，不继承示例项目许可。

模板按需填入真实内容，无内容的章节删除。文献阅读或教学项目不预建run、实验账本或CLAIMS。建立实验计划时配对Results并注明未执行；Git初始化、提交及远程动作遵循用户范围，不从模板推定提交授权。

旧项目升级：

1. 读取当前AGENTS、相关INDEX及反馈；区分当前规则与被替代的历史建议。
2. 记录完整包来源路径、声明版本、源仓库commit及未提交差异、文件清单和SHA256。版本号相同不证明内容相同。
3. 提出实质冲突及本次迁移范围。普通规则维护不能放宽权限、成本上限或证据接纳。
4. 应用获准变化；原始材料、accepted run、旧计划设计和原始反馈保留。必要时以相对链接和迁移映射保留旧路径。
5. 核对文件字节、引用、入口及调用脚本。先检查受影响范围；既有问题单列，不虚报全仓通过。

项目安装副本记录上游版本及本地差异。此包不自动升级其他项目、不更新持久记忆、不触发新实验。脚本只检查链接与计划/Results对应，可显式选择扫描范围。旧sync可由旧项目继续使用，但新结构不依赖它。


## 模板落点与工具入口

[目录管理映射](index-management.md)列出模板与任务。knowledge-index落到00_knowledge/00_INDEX.md，subplans-index落到02_subplans/00_INDEX.md，results-index落到03_results/00_INDEX.md；concepts-index与concept-topic-index分别落到Concepts总入口与实际专题。literature-index落到01_literature/00_INDEX.md，SOURCE落到真实文献key目录。其余模板只在对应目录实际启用时实例化。

填入真实路径和内容，并将需要的管理细则保留在项目INDEX，不能只留下“详见skill”。修改示例路径时从最终文件位置检查相对链接；无实际内容的表格行或可选目录不创建。项目有不同编号/布局时映射到现有位置，不重排历史身份。

如需根project.py命令，可使用一个只转发到实际安装包scripts/project.py的入口，显式传入项目根；也可直接运行安装包脚本。不能写文档宣称有根命令而未部署入口。安装位置与包版本在项目维护记录中写明。

规则更新时只改获准范围，维护对应INDEX和AGENTS路由；不要求重跑历史实验或把全部旧文重排。未部署的上游新版本不能在项目中标成已升级。公开发布前区分通用文件和本机来源清单。

## v0.6.0已初始化项目的补齐步骤

这是内容完整性升级，不能只改版本号或复制新SKILL.md。先核对当前AGENTS、计划INDEX与计划/Results、Concepts总入口与实际文章、报告及其他启用目录的INDEX；分别列出已有、缺失、项目定制和历史记录。不能因为路径存在就判定管理细则已部署。

重点核对：Phase状态是否只有一个权威位置；每阶段是否有依赖、动作、交付、验证及恢复条件；Concepts是否有适合实际规模的组织和读懂记录；报告是否能定位版本、证据截止与实际交付；现有数据/上游/运行是否能追溯版本。相对链接从落点验证，未来文件路径写代码文本，不生成不存在的链接。

生成具体差异后仅在获准项目应用。保留Results维护阶段执行表等有效本地选择，保留无Git项目的明确源码快照版本方案；不套上游项目机器、预算、阶段状态词或目录编号。平铺Concepts不自动迁移，旧阅读记录不自动重判。模板升级、项目部署、Git提交和远程发布分别记录；部署报告写清哪些INDEX已补齐，哪些保留、未改或仍缺输入。
